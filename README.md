# Q-HEART — Quantum Hardware Evaluation & Classification Benchmark

Q-HEART is a reproducible benchmark for Qiskit Fall Fest 2026 Phase 1, official problem PS-Q1 (Variational Quantum Classifier), prepared for SRM University-AP. It compares one fixed four-logical-qubit VQC workflow when compiled to two synthetic processor coupling maps.

This is a synthetic machine-learning benchmark, not a clinical diagnostic system. The dataset is generated by `sklearn.datasets.make_classification`; no patient or clinical data is used. The processor graphs are participant-defined architecture models, not claims about IBM or other commercial hardware.

## Research question

With the dataset, model, transpiler settings, and noise assumptions held constant, what held-out classification accuracy and compilation cost result from targeting Processor A versus Processor B?

## Method

- Dataset: 200 samples, four features, three informative features, `n_redundant=0`, binary labels, `random_state=42`.
- Split: stratified 80/20 split with `random_state=42` (160 train, 40 test).
- Preprocessing: `StandardScaler` for the classical baseline and a `MinMaxScaler(0, π)` for angle encoding; both are fit on training data only.
- VQC: exactly four logical qubits. Each feature is encoded as a parameterized `Ry` rotation, followed by a nearest-neighbor CNOT layer, trainable `Ry` rotations, a reversed CNOT layer, and trainable `Rz` rotations.
- Loss: binary cross-entropy from the expectation of Z on logical qubit 0. The measurement rule is `p(class=1) = (1 - <Z>)/2`, with a threshold of 0.5.
- Optimizer: COBYLA, 30 function-evaluation budget, seed-42 initialization. The generated loss history records each objective evaluation.
- Classical reference: logistic regression, `max_iter=1000`, `random_state=42`.

## Processor models and compilation

Processor A has five nodes and edges `[(0,1), (1,2), (1,3), (3,4)]`.

Processor B has nine nodes and edges `[(0,1), (1,2), (1,6), (2,3), (2,6), (2,5), (3,4), (4,5), (5,6), (6,7), (6,8), (8,0)]`.

The same parameterized logical circuit is transpiled to both maps with basis gates `rz,sx,x,cx`, optimization level 1, and `seed_transpiler=42`. In this run both topologies produced depth 18 and six CX gates. The logical circuit itself has six CX gates, so the reported CX routing overhead is zero and explicit SWAP count is zero. This means the selected layout fit the circuit's nearest-neighbor interactions; it does not mean routing is free for other circuits or that the physical graphs are equivalent.

## Noise model

Aer receives an actual `NoiseModel`: depolarizing error 0.001 is attached to `rz`, `sx`, and `x`; depolarizing error 0.005 is attached to `cx`; and each measured qubit receives a symmetric readout error with 0.01 probability for either bit flip. Ideal and noisy evaluations use Aer shot simulation with 4096 shots per test sample and seed 42 (offset by the sample index for repeatable per-sample streams).

## Run it

From the repository root, using Python 3.11:

```powershell
uv venv .venv --python 3.11
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
.venv\Scripts\python.exe main.py
```

The script regenerates all CSV, JSON, and PNG artifacts under `results/`. In the Codex execution environment used for verification, the runtime was placed outside OneDrive because compiled DLL imports were denied by the synced folder; the repository command above remains the intended clean-environment command.

## Artifacts

- `main.py` — authoritative executable benchmark.
- `processors/processor_A.json`, `processors/processor_B.json` — graph, compilation, and noise configuration.
- `results/results.csv` — one row per actual baseline/VQC/architecture evaluation.
- `results/architecture_metrics.csv` — graph and compiled-circuit metrics including layout and settings.
- `results/training_history.csv`, `results/run_metadata.json` — convergence and reproducibility records.
- `results/processor_A_coupling.png`, `results/processor_B_coupling.png` — coupling-map diagrams.

- `Q_HEART_Phase1.ipynb` and `Q-HEART-starter-files.zip` — preserved upstream starter materials; `main.py` is the authoritative Phase 1 implementation.

## Limitations and reproducibility

The optimizer stopped at its evaluation budget rather than reporting convergence (`Maximum number of function evaluations has been exceeded`), but it completed a genuine 29-evaluation training run and produced a held-out prediction. Aer results are synthetic noise simulations, not hardware measurements. Layout strings are recorded exactly as returned by Qiskit and may include ancilla registers introduced by transpilation. Run metadata records Python 3.11.15 and the tested pinned package targets.
